# SEO (en + ja) Implementation Plan

> Plan only. Doesn't touch files the custom-CSV work is changing (`src/lib/**`, upload/mapping panels).

**Goal:** spendlook.app ranks for its own name and for "bank/PayPay CSV spending dashboard" queries in English and Japanese (家計簿 CSV, 三菱UFJ CSV, PayPay CSV). Search results and link previews show the correct language.

## Current state

- Client-only SPA (Vite + TanStack Router) served as Cloudflare static assets with SPA fallback.
- `index.html` has only `<title>spendlook</title>`: no description, OG tags, canonical, robots.txt or sitemap.
- The locale comes from localStorage or `navigator.language`. A crawler only ever sees English, and the Japanese version has no URL of its own.
- Every route except `/` shows private IndexedDB data. A crawler would see empty pages there.

## Decisions

- **Index only the home page, in two languages: `/` (en) and `/ja` (ja).** `/accounts/*` and `/settings` get `noindex` because they are empty for crawlers and private for users.
- **The Japanese version gets its own URL instead of content negotiation.** Google doesn't send `Accept-Language` and advises against redirects based on it. We don't auto-redirect.
- **`/ja` is served by a second static HTML file, `ja.html`,** using Vite's multi-page `input`. Cloudflare's default `auto-trailing-slash` serves `/ja` from `ja.html` with no slash, so it matches the router path `/ja`. No SSR and no prerender dependency.
- **Head tags are static per HTML file,** so crawlers and link-preview bots that don't run JS still see them. Two hand-written HTML files is fine at this size. Mark both with a "keep in sync" comment.
- **Locale precedence:** the `/ja` path wins (and is saved). Otherwise the saved locale is used, then `navigator.language`. On the home page the locale toggle navigates `/` ↔ `/ja`. On other pages it only switches the language, as it does today.
- **Crawlable body text:** a short intro (h1, one paragraph, 3 bullets: private/local, MUFG + PayPay + any CSV, AI categories with your own key). It appears statically inside `#root` in each HTML file and is replaced when React mounts. It is also rendered by `AccountsPage` when there are no accounts. That helps new users too, and Google's rendered DOM keeps the text.
- **Skipped:** per-route `<title>` management, prerender/SSR, blog/content pages, and a localized OG image (one image without text covers both). Add these when there is a reason to.

## Tasks

1. **Head tags in `index.html`**
   - Add `<meta name="description">` and `<link rel="canonical" href="https://spendlook.app/">`.
   - Add `hreflang` alternates: `en` → `/`, `ja` → `/ja`, `x-default` → `/`.
   - Add OG/Twitter tags: `og:title`, `og:description`, `og:url`, `og:image`, `og:locale=en_US`, `og:locale:alternate=ja_JP`, `twitter:card=summary_large_image`.
   - Add `<meta name="theme-color">`.
   - Add a `WebApplication` JSON-LD block (`applicationCategory: FinanceApplication`, `offers.price: 0`, `inLanguage`). CSP doesn't block it because JSON-LD isn't executed.
2. **`ja.html`:** a copy of `index.html` with `lang="ja"`, Japanese title and description, canonical `https://spendlook.app/ja`, the same hreflang set, and `og:locale=ja_JP`.
   - Draft copy (user to review):
     - title: `spendlook — 銀行・PayPayのCSVで支出を見える化`
     - description: `三菱UFJ銀行やPayPayのCSVを読み込むだけの家計ダッシュボード。データはブラウザ内だけに保存。AI分類は自分のAPIキーで。`
3. **`vite.config.ts`:** add `build.rolldownOptions.input = { main: 'index.html', ja: 'ja.html' }`. Check that `dist/ja.html` is emitted and shares chunks with the main entry.
4. **Router + i18n**
   - `src/router.tsx`: add a `/ja` route that renders `AccountsPage`.
   - `src/i18n.ts` `initialLocale()`: return `'ja'` when `location.pathname === '/ja'`.
   - `setLocale`: also set `document.title`, so a user on the ja UI sees a ja tab title.
   - `src/components/locale-toggle.tsx`: on `/` or `/ja`, navigate to the other one.
   - Nav logo link: go to `/ja` when the locale is ja.
5. **Intro block**
   - Add the static intro markup to both HTML files inside `#root`.
   - Add the same text as Lingui `<Trans>` in `AccountsPage`'s empty state, then run `bun run i18n` and fill in `ja.po`.
   - Hold this task until the custom-CSV branch merges, since `accounts.tsx` is likely in flux there.
6. **`public/robots.txt`:** `Allow: /`, `Disallow:` nothing (noindex is handled with headers so Google can still read it), and `Sitemap: https://spendlook.app/sitemap.xml`.
7. **`public/sitemap.xml`:** two `<url>` entries (`/` and `/ja`), each with `xhtml:link` hreflang alternates.
8. **`public/_headers`:** add `X-Robots-Tag: noindex` for `/accounts/*` and `/settings`.
9. **`public/og.png`:** 1200×630, logo and wordmark, no text that needs translating.
10. **Verify**
    - Run `bun run build`. Check that `dist/ja.html` exists with ja tags and that `bun run preview` serves `/ja` in Japanese.
    - After deploy, run `curl -sI` against `/ja` (200, no redirect) and `/settings` (has `X-Robots-Tag`; confirm `_headers` applies to SPA-fallback responses), and `curl -s /ja | grep hreflang`.
    - Check the Google Rich Results test and the URL Inspection rendered HTML for `/` and `/ja`.
    - Paste both URLs into an OG preview tool.
    - Manual (user): add the site to Google Search Console and Bing Webmaster Tools, and submit the sitemap.

## Review focus

1. The two HTML files' scripts and CSP-relevant tags stay identical; only the copy differs.
2. `/ja` never redirects or loops (Cloudflare trailing slash vs. the router).
3. A user with a saved `en` locale who opens `/ja` gets ja. Toggling on other pages works as it does today.
4. Private routes return `noindex`, and robots.txt doesn't block them, so the noindex is actually seen.
